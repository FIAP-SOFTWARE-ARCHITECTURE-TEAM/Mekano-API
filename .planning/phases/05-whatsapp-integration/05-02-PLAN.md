    ```java
    void aoConfirmarPagamento(@Observes(during = TransactionPhase.AFTER_SUCCESS) PagamentoConfirmadoEvent event) {
        // 1. Resolve OS → cliente UUID + veiculo UUID
        var os = osRepository.findById(event.osUuid())
                .orElseThrow(() -> new AppException(404, Messages.get("os.nao.encontrada", event.osUuid())));

        // 2. Resolve cliente → Telefone
        var cliente = clienteRepository.findById(os.getClienteId())
                .orElseThrow(() -> new AppException(404, Messages.get("cliente.nao.encontrado", os.getClienteId())));

        if (cliente.getTelefone() == null) {
            log.warn("Cliente {} não possui telefone cadastrado — ignorando notificação WhatsApp", os.getClienteId());
            return;
        }

        // 3. Resolve veículo → Placa
        var veiculo = veiculoRepository.findById(os.getVeiculoId())
                .orElseThrow(() -> new AppException(404, Messages.get("veiculo.nao.encontrado", os.getVeiculoId())));

        // 4. Send retirada notification
        // Per D-08: message with placa, osUuid link, oficina info
        notifier.notificarRetirada(
                cliente.getTelefone().getValue(),
                cliente.getNome(),
                veiculo.getPlaca().getValue(),
                os.getId());
    }
    ```

    Import `jakarta.enterprise.event.TransactionPhase`.

    **3. Create application service: `WhatsAppWebhookService.java`**

    Package: `com.fiap.mekano.application.service.whatsapp`

    `@ApplicationScoped`, constructor injection:
    - `OrcamentoServicePort orcamentoService` (use port injection — per D-01 transactions in service layer)

    Methods:

    ```java
    public boolean validateApiKey(String apiKey) {
        return webhookSecret.equals(apiKey);
    }

    @Transactional
    public void processButtonReply(String selectedButtonId) {
        // selectedButtonId format: "approve_orc_<uuid>" or "reject_orc_<uuid>"
        if (selectedButtonId == null || selectedButtonId.isBlank()) {
            throw new AppException(400, "Invalid button reply: missing selectedButtonId");
        }

        if (selectedButtonId.startsWith("approve_orc_")) {
            UUID orcamentoUuid = UUID.fromString(selectedButtonId.substring("approve_orc_".length()));
            orcamentoService.aprovar(new AprovarOrcamentoCommand(orcamentoUuid));
        } else if (selectedButtonId.startsWith("reject_orc_")) {
            UUID orcamentoUuid = UUID.fromString(selectedButtonId.substring("reject_orc_".length()));
            orcamentoService.reprovar(new ReprovarOrcamentoCommand(orcamentoUuid, "Recusado via WhatsApp"));
        } else {
            throw new AppException(400, "Unknown button action: " + selectedButtonId);
        }
    }
    ```

    **CRITICAL: `processButtonReply` MUST have `@Transactional`** because it calls `orcamentoService.aprovar()` / `reprovar()` which needs a transaction (per RESEARCH.md Pitfall 3). The webhook resource remains non-transactional per D-01.

    **4. Create REST resource: `WhatsAppWebhookResource.java`**

    Package: `com.fiap.mekano.rest.api`

    `@Path("/webhooks/whatsapp")`, `@RequestScoped`, **`@PermitAll`** (webhook needs no auth — Evolution API is on internal Docker network, auth is via apikey header validation).

    Inject `WhatsAppWebhookService` via constructor.

    ```java
    @POST
    @Consumes(MediaType.APPLICATION_JSON)
    @Produces(MediaType.APPLICATION_JSON)
    @Operation(summary = "Receive WhatsApp webhook from Evolution API",
               description = "Processes button replies (approve/reject orçamento) from WhatsApp")
    @APIResponse(responseCode = "200", description = "Webhook processed")
    @APIResponse(responseCode = "401", description = "Invalid API key")
    public Response receiveMessage(
            @HeaderParam("apikey") String apiKey,
            WebhookPayload payload) {

        // 1. Validate API key per D-10 (webhook security — agent's discretion area)
        if (!webhookService.validateApiKey(apiKey)) {
            return Response.status(Response.Status.UNAUTHORIZED)
                    .entity(new WebhookResponse("error", "Invalid API key"))
                    .build();
        }

        // 2. Only process MESSAGES_UPSERT with buttonsResponseMessage
        if (payload == null || payload.data() == null || payload.data().message() == null
                || payload.data().message().buttonsResponse() == null) {
            return Response.ok(new WebhookResponse("ignored", "Not a button response")).build();
        }

        // 3. Extract button ID and process
        String selectedButtonId = payload.data().message().buttonsResponse().selectedButtonId();
        webhookService.processButtonReply(selectedButtonId);

        return Response.ok(new WebhookResponse("success", "Button reply processed")).build();
    }
    ```

    Add `@Tag(name = "WhatsApp Webhook", description = "Webhook para callbacks do Evolution API")` and OpenAPI method annotations.

    Add `@Slf4j` for logging — log `selectedButtonId` (not the entire payload which contains PII like phone number via `remoteJid`). Log only the actionable information.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05 | Spoofing | WhatsAppWebhookResource | mitigate | Validate `apikey` header against `EVOLUTION_WEBHOOK_SECRET`. Return 401 if invalid (per RESEARCH.md §Security Domain patterns). |
| T-05-06 | Tampering | WhatsAppWebhookService.processButtonReply | mitigate | Extract orcamento UUID from known prefix `approve_orc_` / `reject_orc_`. | T-05-07 | Information Disclosure | Webhook payload logging | mitigate | Log only `selectedButtonId` — NEVER log the full payload which contains `remoteJid` (phone number PII). Log `"Processing button reply: approve_orc_<redacted>"` with UUID truncated. |
| T-05-08 | Elevation of Privilege | processButtonReply without proper auth | mitigate | The webhook is @PermitAll intentionally (Evolution API is on internal Docker network). Auth is validated via apikey header at the resource level BEFORE calling the service. The internal approve/reject flows check orcamento status (must be AGUARDANDO_APROVACAO — handled by OrcamentoService). |
| T-05-09 | Repudiation | processButtonReply without @Transactional | mitigate | processButtonReply MUST have @Transactional (RESEARCH.md §Pitfall 3). Verified by grep. Without a transaction, a partial approve (in-memory but not persisted) could return 200 but leave DB unchanged. |
</threat_model>
