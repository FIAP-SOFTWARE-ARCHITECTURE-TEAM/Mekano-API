<decisions>
## Implementation Decisions

### Acesso Público (AUTH-03, OS-10, OS-11, OS-15)
- **D-01:** Os 3 endpoints de interação do cliente viram `@PermitAll` (sem autenticação):
  - `GET /api/v1/os/{id}/status`
  - `POST /api/v1/orcamentos/{uuid}/aprovar`
  - `POST /api/v1/orcamentos/{uuid}/reprovar`
- **D-02:** Sem mecanismo de código de acesso — o UUID da OS/orçamento é efetivamente a chave de acesso (aceito como risco MVP acadêmico)
- **D-03:** Demais endpoints (CRUD, diagnóstico, execução, pagamento, entrega) permanecem `@RolesAllowed`

### Pipeline de Estoque (EST-03, EST-04, EST-08)
- **D-04:** Semântica: **reserva na aprovação, débito no início da execução** (fiel à spec EST-03/EST-08)
- **D-05:** Reserva modelada como **coluna `saldoReservado`** na peça (nova migration V34). Reserva: `saldoReservado += qtd` se disponível (`saldo - saldoReservado >= qtd`). Débito na execução: `saldo -= qtd`, `saldoReservado -= qtd`. Estoque mínimo considera o saldo disponível
- **D-06:** `OrcamentoService.aprovar` passa a publicar `OrcamentoAprovadoEvent` (que conecta `PecaOrcamentoObserver`)
- **D-07:** Requisição de Compra (EST-04) criada **no observer da aprovação**: para cada peça com disponível < qtd, cria `RequisicaoCompra` com o item faltante (status PENDENTE), reusando `RequisicaoCompraService` + fluxo NfEntrada existente
- **D-08:** Cancelamento de OS libera a reserva (`saldoReservado -= qtd`)

### Idempotência de Pagamento (PAG-02)
- **D-09:** `ProcessedEventRepositoryImpl` (+ `ProcessedEventEntity` + V30) passa a ser o bean `@ApplicationScoped` ativo; `ProcessedEventsRepositoryStub` deixa de ser o bean default
- **D-10:** Chamada duplicada = **no-op silencioso (200)** com estado atual — compatível com retries de webhook

### Audit Trail
- **D-11:** Auditar **todas** as transições de status da OS via `OsAuditEventPublisher` → `OsAuditLogObserver` → `os_audit_log` (create, diagnóstico, aprovação, execução, finalização, pagamento, entrega, cancelamento) — alinhado com D-20 da Fase 3
- **D-12:** Alinhar eventos de entrega: `EntregaConfirmadaEvent` (publicado) vs `OSEntregueEvent` (escutado) — garantir que o listener audit correto seja disparado

### SLA (OS-12)
- **D-13:** `SlaExpiryJob` passa a cancelar a OS: transição `AGUARDANDO_APROVACAO → CANCELADA` com motivo "SLA expirado" (policy 72h mantida, job a cada 12h — D-18..20 da Fase 2)
- **D-14:** Cancelamento por SLA libera reserva de estoque se houver

### Bugs (OS-02, AUTH-04)
- **D-15:** `ClienteService.updateCliente` aplica os campos do comando (corrige no-op atual)
- **D-16:** `shared.exception.AppException` passa a ser mapeada pelo `ApiExceptionMapper` (409 em vez de 500) — ou `AdminUserService` passa a lançar `domain.exception.AppException`

### Verificação Formal
- **D-17:** Gerar VERIFICATION.md retroativos para as 3 fases + atualizar traceability em REQUIREMENTS.md (37/37 Complete) + marcar nyquist

### the agent's Discretion
- Detalhes técnicos de implementação seguem padrões existentes (two-class repository, MapStruct CDI, @Transactional no service, CDI events)
- Estrutura de testes segue padrão (JUnit 5 + Mockito + REST Assured + AssertJ)

</decisions>
