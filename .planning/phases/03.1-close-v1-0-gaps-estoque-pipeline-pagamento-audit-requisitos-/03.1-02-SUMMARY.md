**Reserva atômica de estoque (coluna saldo_reservado, V34) com operações UPDATE guardadas, estoque mínimo por saldo disponível, e pecaId opcional nos itens de orçamento com serialização retrocompatível**

## Accomplishments

- V34 migration adiciona coluna `saldo_reservado BIGINT NOT NULL DEFAULT 0` à tabela pecas (H2-compatível, coluna única)
- `Peca.saldoReservado` (Long) no domínio com `disponivel() = saldoAtual - saldoReservado` e `isEstoqueMinimoAtingido()` usando disponível
- 3 operações atômicas no `PecaRepositoryImpl` com guardas SQL no WHERE: `reservarSaldo` (`(saldo - saldo_reservado) >= :qtd`), `debitarSaldoReservado` e `liberarReserva` (`saldo_reservado >= :qtd`)
- `ItemOrcamento.pecaId` (UUID, nullable) com construtor 4 args; 3-arg existente delega com pecaId=null (retrocompatível)
- `OrcamentoEntityMapperImpl` serializa/desserializa 4 campos pipe-separados (desc|qtd|valor|pecaId) com split(part,4) mantendo retrocompatibilidade com linhas legadas de 3 campos
- `finalizarDiagnostico` branch PECA agora propaga `peca.getId()` no `ItemOrcamento`
- Todos os 5 call sites de `Peca.reconstitute` atualizados com novo parâmetro `saldoReservado`
