<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client → GET /os/{id}/status | input não autenticado cruza aqui (UUID na path) |
| anonymous client → POST /orcamentos/{uuid}/aprovar\|reprovar | mutação não autenticada com UUID como chave |
| authenticated admin → /admin/usuarios | input autenticado; erro de duplicidade deve ser 409 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-031-01 | Information Disclosure | GET /os/{id}/status público | accept | D-02: UUID da OS é a chave de acesso (risco aceito para MVP acadêmico); resposta limitada a id/status/createdAt — sem dados do cliente/veículo. Documentado em 03.1-CONTEXT.md |
| T-031-02 | Spoofing | POST /orcamentos/{uuid}/aprovar\|reprovar público | accept | D-02: UUID do orçamento é a chave (não enumerável na prática); transição valida estado via matriz StatusOS.podeTransicionarPara (estado já aprovado/expirado → 422) |
| T-031-03 | Tampering | OrcamentoResource class-level @RolesAllowed vs método @PermitAll | mitigate | Teste negativo anônimo garante que apenas aprovar/reprovar/status são públicos; demais métodos seguem 401 (verificado por teste) |
| T-031-04 | Information Disclosure | shared AppException vazando stack/500 | mitigate | Branch novo no ApiExceptionMapper devolve status + mensagem da exceção em RFC 7807; exceções não mapeadas seguem 500 genérico |
</threat_model>
