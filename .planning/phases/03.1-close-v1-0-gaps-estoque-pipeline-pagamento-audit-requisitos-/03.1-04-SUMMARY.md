## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] HQL query in ProcessedEventPanacheRepository used column name instead of entity field name**
- **Found during:** Task 3 — PagamentoResourceTest E2E failures (500 Internal Server Error)
- **Issue:** `count("evento_id = ?1", ...)` used SQL column name `evento_id` but HQL requires entity field name `eventoId`
- **Fix:** Changed to `count("eventoId = ?1", ...)` in both `eventoJaProcessado()` and `buscarPorEventoId()`
- **Files modified:** `ProcessedEventPanacheRepository.java`
- **Root cause:** The stub was always active, masking this bug. When the real impl took over, the incorrect HQL surfaced.

**2. [Rule 3 - Blocking] PagamentoResourceTest E2E needed initial stock for peca**
- **Found during:** Task 3 — iniciarExecucao returning 409 because peca had 0 stock
- **Issue:** The new iniciarExecucao pipeline debits reserved stock, but the E2E test created pecas with 0 saldoAtual
- **Fix:** Added `@Inject PecaRepositoryPort pecaRepository` and `pecaRepository.creditarSaldo(UUID.fromString(pecaId), 10)` after peca creation
- **Files modified:** `PagamentoResourceTest.java`

**3. [Rule 3 - Blocking] Strict Mockito stubbing conflict in OrdemDeServicoServiceTest**
- **Found during:** Task 2 — `iniciarExecucaoReservaInsuficienteLanca409` failed with UnnecessaryStubbingException
- **Issue:** setUp() stubs conflicted with test methods that overrode the same mock
- **Fix:** Added `@MockitoSettings(strictness = Strictness.LENIENT)` at class level
- **Files modified:** `OrdemDeServicoServiceTest.java`
