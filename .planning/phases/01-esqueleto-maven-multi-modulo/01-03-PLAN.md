  <action>
Criar o arquivo `docker-compose.yml` na raiz do projeto (mesmo nível de `pom.xml`) com o conteúdo exato abaixo.

**Decisões de design:**
- `postgres:16-alpine` — mesma versão usada pelo Quarkus DevServices (consistência dev/test)
- `${POSTGRES_USER:-mekano}` — suporta override via arquivo `.env` na raiz; default `mekano`
- `healthcheck` com `pg_isready` permite `depends_on: condition: service_healthy` em futuros serviços
- `start_period: 10s` — dá tempo para PostgreSQL inicializar antes de contar falhas de health
- Volume nomeado `postgres_data` — dados persistem entre `docker-compose down` e `up`

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:16-alpine
    container_name: mekano-postgres
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: mekano
      POSTGRES_USER: ${POSTGRES_USER:-mekano}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-mekano}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-mekano} -d mekano"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

volumes:
  postgres_data:
    driver: local
```

**REGRA CRÍTICA — Perfil %test:**
A linha `%test.quarkus.datasource.jdbc.url` NÃO DEVE EXISTIR. A ausência desta propriedade é o mecanismo pelo qual o Quarkus ativa DevServices (Testcontainers) automaticamente no perfil test. Qualquer URL no %test desativa o DevServices e quebrará os testes das Fases 4 e 5.

**Conteúdo do arquivo:**

```properties
# =============================================================================
# Mekano — Application Configuration
# =============================================================================

# --- Datasource global ---
quarkus.datasource.db-kind=postgresql

# --- Perfil %dev: aponta para docker-compose (DEV-02) ---
# Iniciar com: docker-compose up -d && ./mvnw quarkus:dev -pl mekano-adapter -am
%dev.quarkus.datasource.username=mekano
%dev.quarkus.datasource.password=mekano
%dev.quarkus.datasource.jdbc.url=jdbc:postgresql://localhost:5432/mekano

# --- Perfil %prod: variáveis de ambiente obrigatórias ---
%prod.quarkus.datasource.username=${DB_USER:mekano}
%prod.quarkus.datasource.password=${DB_PASSWORD:mekano}
%prod.quarkus.datasource.jdbc.url=${DB_URL:jdbc:postgresql://localhost:5432/mekano}

# --- Perfil %test: SEM jdbc.url → Quarkus ativa DevServices (Testcontainers) automaticamente ---
# INTENCIONAL: não declarar jdbc.url no test. quarkus-jdbc-postgresql detecta a ausência
# e inicia um container PostgreSQL automaticamente via Testcontainers.
%test.quarkus.datasource.devservices.image-name=docker.io/library/postgres:16-alpine

# --- Hibernate ORM ---
%dev.quarkus.hibernate-orm.log.sql=true
%prod.quarkus.hibernate-orm.log.sql=false
%dev.quarkus.hibernate-orm.schema-management.strategy=validate
%prod.quarkus.hibernate-orm.schema-management.strategy=validate

# --- Flyway (Gotcha 4: migrate-at-start=false por padrão — declarar explicitamente) ---
quarkus.flyway.migrate-at-start=true
quarkus.flyway.connect-retries=5

# --- OpenAPI / Swagger UI (EXT-04, ADP-07) ---
quarkus.swagger-ui.always-include=true
```

**Notas de implementação:**
- `quarkus.datasource.db-kind=postgresql` sem prefixo de perfil aplica a todos os perfis
- `%dev.quarkus.hibernate-orm.schema-management.strategy=validate` previne que Hibernate crie/drope schema conflitando com Flyway (Gotcha 4 adjacente)
- `quarkus.flyway.connect-retries=5` tolera latência do Docker container na inicialização

<threat_model>
## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| dev workstation → PostgreSQL container | Credenciais hardcoded em docker-compose (dev apenas; sem dados reais) |
| application → banco de dados | Credenciais de produção via variáveis de ambiente (não no código-fonte) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | application.properties — credenciais %dev | accept | Credenciais hardcoded são `mekano/mekano` para banco local de dev; nenhum dado sensível; arquivo commitado por design (dev onboarding) |
| T-03-02 | Information Disclosure | application.properties — credenciais %prod | mitigate | `%prod` usa `${DB_USER}`, `${DB_PASSWORD}`, `${DB_URL}` — variáveis de ambiente injetadas em runtime; nunca hardcoded no código-fonte |
| T-03-03 | Tampering | docker-compose.yml — imagem PostgreSQL | accept | `postgres:16-alpine` é imagem oficial Docker Hub; digest pinning (postgres:16-alpine@sha256:...) seria melhor mas está fora do escopo desta fase |
| T-03-04 | Denial of Service | DevServices ativado inadvertidamente em %prod | mitigate | `%prod.quarkus.datasource.jdbc.url` explícita desativa DevServices em produção; Quarkus só ativa DevServices quando URL está ausente no perfil ativo |
</threat_model>
